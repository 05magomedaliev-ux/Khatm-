# Хатм — наш путь

Telegram Mini App для коллективного чтения Корана: учёт страниц, задолженность, два рейтинга, календарь, достижения и бот с напоминаниями.

Стек: React + TypeScript + Vite, Node.js + Express, PostgreSQL (Supabase) с Row Level Security, grammY.

```
packages/shared   расчёты (долг, серии, рейтинги, достижения) и типы API
apps/web          Mini App
apps/server       API, бот, планировщик уведомлений
supabase          миграции и первая группа
scripts           резервное копирование
```

## Бесплатный запуск на Render

Нужны бот, проект Supabase и Web Service на Render с окружением Docker и тарифом Free. Вручную задаются только `DATABASE_URL`, `BOT_TOKEN` и `BOT_USERNAME`. Адрес приложения, режим бота, таблицы и первая группа настраиваются автоматически, SQL выполнять не нужно. В журнале сервиса появится строка «Первая ссылка: ...»: откройте её раньше остальных.

Бесплатный сервис засыпает через 15 минут без запросов. Чтобы работали напоминания, настройте на cron-job.org запрос к `https://адрес/api/health` каждые 10 минут.

## Запуск за шесть шагов

### 1. Бот
В [@BotFather](https://t.me/BotFather): `/newbot`, сохраните токен и имя бота.

### 2. База
1. Создайте проект в [Supabase](https://supabase.com).
2. Откройте SQL Editor и выполните по очереди содержимое файлов:
   - `supabase/migrations/20261108000001_schema.sql`
   - `supabase/migrations/20261108000002_security.sql`
   - `supabase/seed.sql`
3. Последний запрос вернёт `invite_code`. Сохраните его: это первое приглашение.

Строка подключения: Project Settings → Database → Connection string → Transaction pooler.

### 3. Настройки
Скопируйте `.env.example` в `.env` и заполните. На хостинге те же значения задаются как переменные окружения.

| Переменная | Что указать |
|---|---|
| `DATABASE_URL` | строка подключения из шага 2 |
| `DATABASE_SSL` | `require` для Supabase |
| `BOT_TOKEN`, `BOT_USERNAME` | из шага 1, имя без @ |
| `WEBAPP_URL` | HTTPS-адрес приложения из шага 4 |
| `BOT_MODE` | `webhook` на сервере, `polling` локально |
| `WEBHOOK_SECRET` | необязательно: длинная случайная строка из букв и цифр |

### 4. Публикация
Подойдёт любой хостинг контейнеров с HTTPS. Для [Render](https://render.com): New → Blueprint, укажите репозиторий (файл `render.yaml` уже есть) и заполните переменные. Если адрес сервиса станет известен только после создания, впишите его в `WEBAPP_URL` и перезапустите сервис.

Без Docker: `npm install && npm run build && npm start`.

После первого `npm install` сохраните созданный `package-lock.json` в репозиторий, чтобы версии зависимостей не менялись.

### 5. Подключение Mini App
Сервер сам ставит кнопку меню и команды бота. По желанию задайте описание и картинку в @BotFather.

### 6. Первый вход
Откройте `https://t.me/<ИМЯ_БОТА>?start=<invite_code>` и выберите своё имя. **Первый подключившийся становится владельцем группы**, поэтому откройте ссылку раньше остальных. Затем перешлите её участникам. В группе уже есть Мурад, Курбан, Закария, Мухаммад и Марат, у всех ноль результатов.

Чтобы итоги дня приходили в общий чат: добавьте бота в чат, в приложении откройте Настройки → Управление группой → Чат группы, получите код и отправьте в чате `/link КОД`.

## Как считается

Весь расчёт находится в `packages/shared/src`. Задолженность не хранится: она каждый раз считается из отчётов, поэтому правка задним числом сама обновляет все последующие дни.

`DebtToday = max(0, DebtYesterday + DailyMinimum − PagesReadToday)`

Решения там, где ТЗ допускало варианты:

| Вопрос | Как сделано | Где изменить |
|---|---|---|
| Долг 2, прочитано ровно 2 | Страницы закрывают долг, норма дня не выполнена, день жёлтый, долг остаётся 2 | `allocateDay` в `ledger.ts` |
| Завершённый день с 1 страницей из 2 | Жёлтый. Красный — завершённый день без единой страницы | `buildLedger` в `ledger.ts` |
| Начало учёта | С дня подключения участника. Администратор может указать другую дату | Управление группой → участник |
| Показатель B | 100 без долга, линейно до 0 при долге в 30 дневных норм | `computeDiscipline` в `stats.ts` |
| Общий процент группы | Вклад каждого ограничен 604 страницами: 100% значит, что завершили все | `groupProgress` в `stats.ts` |
| Смена нормы | Действует с текущего дня, прошедшие дни не меняются | таблица `group_norms` |
| Новый круг после Хатма | Прежние диапазоны не вызывают предупреждений о повторе | `currentCycleReports` в `overlap.ts` |

Отчёт-количество не содержит номеров страниц, поэтому с диапазонами он не сверяется. Предупреждение для него возникает только при одинаковом числе страниц за ту же дату в течение 10 минут, и это лишь догадка.

Религиозных цитат в приложении нет. В библиотеке `motivation.ts` только собственные фразы поддержки. Аят или хадис туда можно добавить только с проверенным источником.

## Безопасность

- Пользователя определяет только подпись `initData`, проверенная на сервере. Срок действия 24 часа.
- Каждый запрос выполняется в транзакции под ролью `khatm_app` с RLS: ошибка в маршруте не откроет чужую группу.
- Публичным ролям Supabase (`anon`, `authenticated`) доступ к таблицам закрыт.
- История отчётов пишется триггером базы, обойти её из приложения нельзя.
- Двойная отправка отсекается уникальным `client_request_id` и блокировкой на участника.

## Резервные копии

Вручную: `DATABASE_DIRECT_URL=... bash scripts/backup.sh`.

Каждую ночь: файл `.github/workflows/backup.yml`. В настройках репозитория добавьте секрет `DATABASE_DIRECT_URL` (прямое подключение или Session pooler). Держите репозиторий приватным: копии содержат данные участников.

Восстановление: `pg_restore --no-owner -d <URL> файл.dump`. Сообщение о том, что схема `public` уже существует, не мешает.

## Разработка

```
npm install
npm run dev:server     # API и бот, нужен .env
npm run dev:web        # интерфейс на :5173, запросы идут на :3000
npm run typecheck
npm test               # интеграционные: TEST_DATABASE_URL=postgres://... npm test
```

Вне Telegram приложение показывает просьбу открыть его через бота. Для локальной проверки используйте туннель с HTTPS и укажите его адрес в `WEBAPP_URL`.
